# 0004. UI 아이콘은 lucide로, 일정 아이콘은 이모지로 그린다

- 상태: 채택
- 날짜: 2026-10-19

## 배경

지금까지 상단 바의 뒤로가기와 공유, 여행 정보 수정, 최근 여행 지우기, 추가 버튼의 아이콘을 `←`, `🔗`, `✏️`, `×`, `＋` 같은 문자로 그렸습니다. 컬러 이모지는 OS마다 그림이 다르고 `color`를 따르지 않아서, [디자인 문서](../design/visual-design.md)의 색 토큰과 "아이콘 대비 3:1 이상" 규칙을 코드로 보장할 수 없었습니다. `←`, `×`, `＋`는 글꼴에 따라 크기와 기준선이 달라져서 버튼 안의 위치가 어긋났습니다.

반면에 **일정 항목**의 아이콘은 사용자가 휴대폰 이모지 키보드로 고르는 데이터입니다(spec 7.4).

## 결정

1. **버튼과 내비게이션에 쓰는 UI 아이콘은 `lucide-react`로 그립니다.** 아이콘은 `currentColor`를 따르므로 색은 버튼의 색 토큰으로 정합니다. 선 굵기는 2.25를 기본으로 하고, 글자 옆에 놓이는 `Plus`는 2.5를 씁니다.
2. **아이콘에는 접근 가능한 이름을 붙이지 않습니다.** lucide가 SVG에 `aria-hidden="true"`를 붙이고, 이름은 버튼의 `aria-label`이나 글자가 맡습니다.
3. **일정 항목의 아이콘과 장식용 그림은 이모지로 둡니다.** 일정 아이콘(`✈️`, 기본값 `📍` 등), 홈 화면의 `🧳`, 여행을 찾지 못한 화면의 `🗺️`, 안내 문장 속 `⏰`가 여기에 해당합니다.

## 검토했다가 버린 선택지

- **문자와 이모지 유지**: 의존성은 늘지 않지만, 위에 적은 OS별 차이와 색·대비 문제가 그대로 남습니다.
- **SVG 직접 작성**: 지금 필요한 아이콘은 5개뿐이지만, 아이콘이 늘어날 때마다 직접 그리고 모양을 맞춰야 합니다.
- **Phosphor**: 굵기와 duotone 선택지가 많지만, 이 정도 아이콘 수에서는 선택지가 오히려 과합니다. lucide는 선 끝이 둥글어 지금의 둥근 시각 방향([ADR 0001](0001-visual-direction-ticket-timeline-peach.md))에 맞고, 아이콘을 하나씩 import하므로 번들에는 쓰는 아이콘만 들어갑니다.

## 결과

- UI 아이콘이 모든 OS에서 같은 모양으로 보이고, 색 토큰을 바꾸면 아이콘 색도 함께 바뀝니다.
- 새 UI 아이콘은 lucide에서 고릅니다. lucide에 없는 아이콘이 필요하면 이 결정을 다시 검토합니다.
- 토스트나 안내 문구에서 아이콘을 문자(예: "🔗를 눌러")로 가리킬 수 없습니다. 이런 문구는 버튼 이름으로 안내합니다.
